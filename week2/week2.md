# 2주차 보고서 — 4×4 변환

## 목표
* 4×4 행렬을 직접 만들고, **적용 순서**가 결과를 바꾼다는 것을 화면과 행렬 양쪽으로 보여 준다.
* 실제 비율(1 AU = 149.6 백만 km)에서 행성 반지름이 얼마나 작은지 수치와 화면으로 확인한다.
* 위성의 변환이 **카메라와 무관**함을 증명한다.

## 파일
* `week2/index.html` — 세 페이지 안내
* `week2/order.html` — 회전 → 이동 vs 이동 → 회전 (두 행렬 동시 출력)
* `week2/scale.html` — 1 AU 단위 선택, 실제/과장 배율 비교
* `week2/satellite.html` — 달 모델 행렬을 카메라 회전 전후로 두 번 읽기
* `week2/common.js` — 공용 렌더러와 행렬 표(`CGW.fmt`, 열 우선 → 행 단위 재배열)

## 구현 요점
* 행렬은 열 우선(column-major). `M = T·R` 이면 정점에는 **R 이 먼저** 적용된다.
  화면 아래쪽 `M = 이동·회전` / `M = 회전·이동` 두 표를 나란히 두어 차이를 즉시 비교할 수 있게 했다.
* 이동행(12~14번)만 읽어도 두 결과의 위치 차이가 드러나도록 결과 문장에 좌표와 거리 차이를 함께 출력한다.
* 실제 비율: 지구 반지름 = 6,371 km, 1 AU = 149,597,870 km → 비율 1/23,481.
  AU 를 10 단위로 두면 지구 반지름은 0.000426 단위가 되어 화면에서 점으로 보인다.
  과장 배율을 곱하면 교재용 그림이 되고, 두 값의 차이를 수치로 함께 보여 준다.
* 위성: `M_moon = T(planet) · R(orbit) · T(r)`. 카메라(뷰 행렬)는 곱셈 순서에서
  뒤쪽(정점에 먼저)에만 관여하므로 모델 행렬을 바꾸지 않는다. 같은 값을 두 번 읽어 비교한다.

## 확인 결과
`week2/images/` 의 세 화면. order 에서 `T·R` 이동열 (2.00, 0, 0.50) vs `R·T` (1.06, 0, −1.77),
satellite 에서 카메라 40°와 200°의 달 행렬이 완전히 동일했다.
