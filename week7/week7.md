## 실습 2 (`week7/task2.html`) — 기기별 자동 설정
* 기기 지문: `WEBGL_debug_renderer_info` 의 GPU 이름 + 코어 수 + deviceMemory + 모바일 여부
  → 31진 해시로 `perf-profile-v1:<hash>` 키를 만든다.
* 첫 실행: 가장 가벼운 단계(320×180·4표본·1회)를 실제로 3회 재어 중앙값 `t0` 을 얻고,
  프로파일별 연산량 `픽셀수 × 표본 × (반사+1)` 비율로 나머지 단계 시간을 **추정**한다.
  (고부하 단계를 그대로 재면 저사양 기기에서 수십 초가 걸리기 때문)
  33 ms(30fps) 예산 안에 들어오는 가장 높은 단계를 고르고 `localStorage` 에 저장한다.
* 새로고침하면 저장된 단계가 즉시 적용된다. 저장값이 없는 기기만 다시 보정한다.
* 프로파일: 저사양(320/4/1, 고급 끔) / 중간(640/8/2) / 고사양(1280/16/3) / 최고(1920/32/4).

## 측정 (참고값)
소프트웨어 렌더러(2코어·4GB VM, 320×180·4표본·1회 반사):

| 방식 | 중앙값 | Local 대비 |
|---|---|---|
| Local (래스터화) | 8.49 ms | 1.0× |
| Ray tracing | 33.62 ms | 4.0× |
| Path tracing | 151.06 ms | 17.8× |

**이 값은 GPU 가 아닌 CPU 소프트웨어 렌더러라서 실제 기기와 비교할 수 없다.**
과제 요구대로 PC·노트북·모바일 중 두 기기 이상에서 각각 `세 방식 측정` 을 눌러
같은 표를 채운 뒤, 아래 해석을 자기 환경에 맞게 고쳐 써야 한다.

## 해석
경로 추적은 표본 수에 거의 비례해 비용이 늘고(4→8표본에서 약 2배), 해상도는 픽셀 수에
비례한다. 그래서 자동 설정은 해상도보다 **표본 수를 먼저 낮추는** 쪽이 체감 개선이 크다.
저사양 기기에서 320×180 으로 떨어뜨려도 30fps 를 겨우 맞추는 경우가 있어,
고급 효과(거울·굴절)를 끄는 것이 마지막 카드가 된다.
